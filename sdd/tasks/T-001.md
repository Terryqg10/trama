# T-001 — Scaffolding estricto y validación de entorno

## Contexto

`package.json` ya declara las dependencias y scripts. Falta la
configuración del proyecto y el esqueleto mínimo para que las puertas 1-3
tengan algo que comprobar. Sin UI de producto.

## Cambio previsto

- `tsconfig.json` con `strict: true`, sin `any` permitido por lint.
- `eslint.config.mjs` (ESLint 9 flat config) con reglas que prohíben `any` y `@ts-ignore`.
- `next.config.ts`, `postcss.config.mjs` (Tailwind 4) y `vitest.config.ts`.
- `src/app/layout.tsx` y `src/app/page.tsx` mínimos, sin estilos propios, para que `next build` funcione.
- `src/lib/env.ts`: esquema Zod de variables de entorno (URL y anon key de Supabase, claves de Stripe). Rechaza claves Stripe `live`.
- `.env.example` con solo nombres, sin valores.
- Test `src/lib/env.test.ts` que recibe objetos de entorno inyectados. Nunca lee `.env*`.

## Fuera de alcance de esta tarea

- Cualquier UI de producto, logo o navegación (T-004).
- Conexión real con Supabase o Stripe.
- CI en GitHub Actions (T-002).
- Migraciones y RLS (T-003).

## Criterios de aceptación

| ID | Dado | Cuando | Entonces |
|---|---|---|---|
| CA-24 | Un entorno con clave Stripe `sk_live_...` | Se valida con el esquema | La validación falla con error explícito |
| CA-24 | Un entorno con claves `test` y URL válida | Se valida con el esquema | La validación pasa y devuelve tipos derivados de Zod |
| CA-25 | Repo con las dependencias instaladas | Se ejecutan `pnpm typecheck`, `pnpm lint` y `pnpm build` | Los tres terminan sin errores |

## Puertas que aplican

- [ ] tsc --noEmit
- [ ] lint
