# T-005a — Datos del catálogo

## Contexto

T-005 (listado) y T-005b (ficha) necesitan productos, imágenes y una forma
tipada y validada de consultarlos. Hoy la BD tiene el esquema (T-003b) pero ningún
producto y ninguna tabla de imágenes. Esta tarea prepara los datos y la capa de
consulta, sin UI. Decisión del usuario: imágenes con ruta relativa y ficheros en
`public/products/` por ahora, y Supabase Storage con el panel (T-010a).

## Cambio previsto

Tabla `product_images` con RLS, datos de ejemplo en SQL con imágenes
placeholder SVG, cliente Supabase de servidor y una capa `lib/catalog` con
filtros y consultas validadas con Zod.

## Fuera de alcance de esta tarea

- Cualquier UI (listado, filtros visibles, ficha): T-005 y T-005b.
- Supabase Storage y subida de imágenes: T-010a.
- Guías de tallas (datos): T-005b.
- Precio de referencia y Ofertas: T-003c. La consulta de Ofertas devolverá vacío
  hasta entonces.
- Fotos reales: las imágenes son placeholders generados, sin derechos de terceros.

## Alcance concreto

| Elemento | Detalle |
|---|---|
| Migración | `product_images` (`product_id`, `path`, `alt`, `position`), `alt` obligatorio, `path` relativo bajo `/products/`, `unique (product_id, position)`. RLS: lectura si el producto es visible (activo o admin) y escritura solo admin. Mismo patrón de privilegios que T-003b. |
| Placeholders | Script Node `scripts/generate-placeholders.mjs` (cross-platform) que escribe SVG en `public/products/` por categoría y color. Sin tipografía ni marcas. |
| Datos de ejemplo | `supabase/seed/catalog-demo.sql`, idempotente (por `slug`). Unos 12 productos: hombre y mujer, las 4 categorías, mezcla de casual y vestir, algunos `is_new`, con variantes de talla y color, algún stock a 0, e imágenes con `alt`. Contenido ficticio, sin marcas reales. Se aplica pegándolo en el SQL Editor. |
| Cliente servidor | `src/lib/supabase/server.ts`: único punto de acceso a Supabase en servidor, con clave pública y tipos generados. Ampliación de `lib/env` con un esquema solo de las variables de Supabase (el actual exige también las de Stripe). |
| Filtros | `src/lib/catalog/filters.ts`: Zod que valida los `searchParams` (género, categoría, talla, color, precio mínimo y máximo, ocasión, solo novedades, orden: novedades / precio ascendente / precio descendente). Rechaza por defecto valores no permitidos. |
| Consultas | `src/lib/catalog/queries.ts`: `listProducts(filtros)` y `getProductBySlug(slug)`, con precio "desde" (mínimo de variantes), imágenes ordenadas y disponibilidad por talla. Respuestas validadas con Zod. |
| Tipos | `pnpm db:types` regenerado tras la migración. |

## Criterios de aceptación

| ID | Dado | Cuando | Entonces |
|---|---|---|---|
| CA-01 | Catálogo con productos de ambos géneros | Se consulta con filtro "mujer" y "blusas" | Solo se devuelven blusas de mujer |

CA-01 se verifica aquí a nivel de consulta (test de integración); la prueba
e2e de la interfaz llega con T-005.

Comprobaciones de la tarea (no son CA nuevos de la spec):
- El filtro de talla solo devuelve productos con esa talla **y stock > 0** (base de CA-27).
- El filtro de ocasión "vestir" solo devuelve productos de vestir (base de CA-32).
- El filtro "solo novedades" solo devuelve `is_new` (base de CA-26).
- Los filtros de precio actúan sobre el precio de las variantes y la ordenación por precio usa el precio "desde".
- Un anónimo no obtiene productos inactivos ni sus imágenes (RLS de `product_images`).
- Un no admin no puede escribir en `product_images`.
- Valores inválidos en los filtros (género desconocido, precio negativo, orden inexistente) se rechazan, no se ignoran en silencio.
- Los SVG placeholder no contienen texto de marca ni enlaces externos.
