# T-092 — Cupón de bienvenida: datos y RLS

## Contexto

Enmienda 41, RF-27. Antes de escribir ningún consumidor, la tabla y su seguridad (puerta 6, RLS antes de consumir datos).

## Cambio previsto

- Migración `supabase/migrations/2026102300xxxx_welcome_coupons.sql`, idempotente y con el mismo estilo que `newsletter_subscribers` (ADR-002): tabla `welcome_coupons` (`id`, `code` único, `email`, `percent_off` por defecto 10 con `check` entre 1 y 100, `created_at`, `expires_at`, `redeemed_at`, `redeemed_order_id`), RLS activada **sin ninguna política** y `revoke all` a `anon` y `authenticated`.
- `orders`: columnas `discount_cents integer not null default 0 check (discount_cents >= 0)` y `coupon_id uuid references welcome_coupons(id)`, con un **índice único parcial** sobre `coupon_id` donde el estado no sea `cancelado`.
- Test de integración `coupons-rls` contra la BD real: visitante, cliente y admin no pueden insertar, leer, cambiar ni borrar; el código es único; un cupón no entra en dos pedidos no cancelados. `pnpm db:types` para regenerar los tipos.

## Fuera de alcance de esta tarea

Generar, validar o canjear cupones (T-093) y las pantallas (T-094). **Aplicar la migración al proyecto de Supabase lo hace el propietario**, a mano (`supabase db query --linked …`, ADR-002), y se documenta en la review.

CA-134 (Enmienda 41).
