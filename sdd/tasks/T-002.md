# T-002 — CI bloqueante en GitHub Actions

## Contexto

El proyecto es de nivel L: exige CI bloqueante. Existe un
`.github/workflows/ci.yml` heredado del OS, pero hoy fallaría: no existe
`.node-version` (lo lee `setup-node`) y `pnpm audit` reporta `braces`
(aceptado en ADR-001 hasta 2026-11-11).

## Cambio previsto

Dejar `ci.yml` y `.node-version` listos para que los mismos comandos de las
puertas 1-5 y 10 se ejecuten en cada PR y push a `main`, con la excepción
de ADR-001 acotada en el tiempo.

## Fuera de alcance de esta tarea

- `git init`, creación del repo remoto y configuración de *branch protection*
  en GitHub (lo hace el usuario; sin ello el CI no es bloqueante de facto).
- Tests de integración con BD real (T-003) y e2e del flujo de compra.
- Cualquier cambio en código de aplicación.
- Ejecutar el workflow en GitHub Actions desde esta sesión.

## Criterios de aceptación

| ID | Dado | Cuando | Entonces |
|---|---|---|---|
| CA-25 | Repo recién clonado, con el workflow de CI | Se ejecutan los mismos comandos que el workflow: `pnpm typecheck`, `pnpm lint`, `pnpm build` | Los tres terminan sin errores |

Criterios de la tarea (comprobaciones, no CA nuevos de la spec):
- El workflow incluye typecheck, lint, check-palette, audit, tests unitarios, build, e2e y gitleaks.
- El paso de audit tolera solo `GHSA-vfj7-8cjw-p6xm` y falla a partir del 2026-11-11 o ante cualquier otro hallazgo alto.
- `.node-version` existe y coincide con una versión soportada (`engines.node >=20`).

## Puertas que aplican

- [ ] tsc --noEmit
- [ ] lint
- [ ] build
- [ ] audit --audit-level=high (con la excepción de ADR-001)
- [ ] gitleaks detect
- [ ] check-palette (el workflow la ejecuta)
- [ ] tests unitarios (nivel M, L)
- [ ] CI bloqueante (nivel L)

No aplican: RLS (sin BD), test:a11y y checklist de interfaz (sin UI nueva), Lighthouse (nivel S).

## Evidencia esperada

En `sdd/reviews/T-002.md`, pegadas:
- Salida de `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build`, `pnpm check-palette`.
- Salida del comando de audit con la excepción.
- Contenido final de `.node-version` y diff del `ci.yml`.
- Nota explícita: el run real en GitHub Actions queda **pendiente** hasta que exista el remoto y la *branch protection*.
