## Problemas conocidos

1. **La migración de `product_images` se aplicó a mano** (SQL Editor) y la BD no registra qué migraciones tiene aplicadas.
2. **El seed no se aplicó al primer intento desde el SQL Editor** y no se supo por qué: los contadores seguían a cero y el usuario no vio ningún mensaje. Se aplicó con `supabase db query --linked -f supabase/seed/catalog-demo.sql`, con la sesión de la CLI del usuario. Conviene usar esa vía para las próximas migraciones y semillas, porque devuelve el error exacto.
3. **El CI no ejecuta los tests de integración** ni tiene los secretos de Supabase. El nivel L lo exige.
4. **El CI en GitHub Actions sigue sin ejecutarse** (sin repo ni remoto).
5. **Los precios, textos y composiciones del seed son ficticios.** No hay marcas reales. Los precios no tienen base de mercado.
6. **Las imágenes son placeholders** (siluetas planas por categoría y color), no fotos. Se cambian por fotos reales con solo cambiar los ficheros o las rutas.
7. **El precio "desde" se calcula sobre las variantes devueltas.** Con un filtro de talla o precio activo, es el menor de las variantes que cumplen el filtro. Está documentado en `queries.ts`.
8. **El orden se hace en el servidor tras la consulta**, con un tope de 200 productos y sin paginación. Suficiente para este catálogo; habría que revisarlo si crece.
9. **Ofertas sigue sin consulta**: depende del precio de referencia (T-003c).
10. **Los tests de integración usan la BD de desarrollo del usuario.** Crean y borran sus datos; se verificó que no queda nada de prueba.
11. Pendientes heredados: avisos de peer-deps de esbuild, `.env.example` sin revisar (permisos), historial git sin escanear.
