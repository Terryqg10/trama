## Hallazgo durante el escaneo de secretos

El escaneo `--no-git` del proyecto completo marcó 2 detecciones `jwt` en **`.env.local`** (líneas 21 y 22), que contiene las claves reales de Supabase. `.env.local` está en `.gitignore` y es el lugar correcto. No es una fuga, pero obliga a escanear una copia sin ese archivo para tener evidencia limpia, que es lo que se hizo. No se mostró ni se leyó ningún valor. Se recomienda no usar `.gitleaks.toml` para ignorar `.env.local`, porque ocultaría un commit accidental del archivo.

## Problemas conocidos

1. **Tipos de BD pendientes** (`pnpm db:types`). El script usa `--local` (Docker); con Supabase en la nube necesita la CLI, `--project-id` y un token. Se resuelve en T-003b. Se aprobó explícitamente (opción A).
2. **La migración se aplicó a mano** en el SQL Editor de Supabase, no con una herramienta que registre qué migraciones están aplicadas. El archivo `supabase/migrations/…` es la fuente de verdad, pero no hay control de versiones de migraciones en la BD.
3. **El CI no ejecuta los tests de integración.** El workflow de T-002 no tiene ese paso ni los secretos de Supabase de pruebas. El nivel L exige tests de integración con BD real en CI bloqueante, así que hay que añadirlo.
4. **El CI en GitHub Actions sigue sin ejecutarse** (sin repo ni remoto).
5. **Los tests de integración usan la BD de desarrollo del usuario.** Crean y borran usuarios de prueba. El usuario confirmó que no quedaron usuarios `rls-…@example.test`.
6. **Enmiendas posteriores:** la Enmienda 3 añade `shop_settings` y `role_audit_log` (T-003d) y que el admin vea email y nombre de clientes. Ninguna invalida esta tarea.
7. Pendientes heredados: avisos de peer-deps de esbuild, `.env.example` sin revisar (permisos), historial git sin escanear.
